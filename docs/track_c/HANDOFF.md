## 2. What was implemented
* `primary_half_capacity` and `primary_double_capacity` in SUMO, with the scenario table tested against `graph_spec.json`. Double: branch lanes x2 plus one E1 approach lane per outgoing lane at P (`network/branch_x2/`). Half: headway tau 3.0 on E4..E10. Realised scale measured: 2.04 / 2.03 and 0.50 / 0.49 (A / B), free-flow unchanged. See `SCENARIOS_AND_FAIRNESS.md`.
* Closure checks: critical route open before 120 s and rejected after, on both networks; only routes A and B remain after closure; per-run counts of closed-link entries, invalid transitions and infeasible routes from the trace.
* `--horizon-s` (default unchanged at 3600 s; Track C plans must set it), `termination`, censoring at the configured horizon.
* Run provenance: `run_config.json` per run (scenario parameters, policy, seed, horizon, SUMO version, network and demand SHA-256, calibration). `run_matrix.py` Track C plans write `manifest.jsonl` (exact command, exit code, `ok` / `invalid` / `failed`, output hashes).
* `independent_batch_copy`: the frozen point-queue decision rule as a separate comparator. Existing policies unchanged.
* `aggregate_track_c.py`, `export_matrix.py`, `tools/reconcile_track_c.py` and the generated report `CROSS_MODEL_TRACK_C.md`.
* CI: the SUMO job now also runs `simulation/sumo/tests` with SUMO installed.

## 4. What failed or is wrong
* First double-capacity attempt (lane doubling only): realised scale 1.00 on route A, because one E1 lane fed both A lanes. Found by calibration, fixed before any scenario run. The failed attempt is described in `SCENARIOS_AND_FAIRNESS.md`.
* In SUMO the shared predictor sends vehicles to route B at manageable and double-capacity load, where static all-A is 4.1% and 9.9% faster. All predictor-based policies are affected equally, so the coordinated-vs-independent comparison stays internally fair, but the predictor overstates route A delay. Cause not isolated; not changed (that would change the policies).
* Pre-existing, Windows only, outside Track C, not fixed: (a) `models/point_queue/wp2_9` golden test fails on Windows because `metric_spec.json` is written with CRLF (identical after removing `\r`; CI on Linux passes), so `tools/run_tests.py` exits 1 on Windows; (b) `tests/test_reconcile_doc.py` rewrites `docs/CROSS_MODEL_RECONCILIATION.md` with CRLF on Windows and leaves it modified.
* `run_config.json` records the network path with the platform separator (backslashes on Windows). The SHA-256 next to it is what identifies the network.
